# Рев’ю та спрощення коду — 2026-10-22

Перевірено поточний робочий стан із наявними незакоміченими змінами. Використано
правила локального скілла `review-agent`; виправлення та рефакторинг виконано
відповідно до прямого запиту користувача.

## Знайдені дефекти

### [P2] Збережіть облік квоти після помилки SQLite — crates/provider-codex/src/usage.rs:174

Для `database = ":memory:"` помилка транзакції закривала з’єднання та скидала
`memory_initialized`. Наступний запит створював порожню базу, забуваючи вже
враховані запити. Це дозволяло повторно витрачати локальний бюджет. Виправлено:
після втрати такої бази цей екземпляр повертає `UsageAccountingUnavailable`.
Файлова база зберігає можливість повторного підключення. Регресійний тест
відтворює втрату таблиці та перевіряє відмову наступних операцій обліку.

### [P2] Повертайте JSON і для помилок аргументів — crates/app-cli/src/lib.rs:160

Невідома команда, некоректна мережа або невідомий параметр повертали текст clap
навіть із `--error-json`. Споживач JSON не міг обробити такі помилки. Виправлено:
режим виводу визначається до розбору аргументів, а помилки отримують код
`invalid_request` і сталий текст без значень аргументів. Інтеграційний тест
перевіряє всі три сценарії, зокрема прапорець після назви команди.

## Що спрощено

- `StrategyPlan.range` і `.volume` тепер обов’язкові посилання. Планувальник
  уже вимагав обидва аналізатори; прибрано два недосяжні варіанти помилки та
  повторні перевірки `Option` під час аналізу.
- У сервісі стратегій повторно використовується один `Candidate`, а метрики
  передаються через переміщення замість зайвих копій.
- Вибір кандидатів повертає результати screening окремою ранньою гілкою.
  Прибрано недосяжну повторну перевірку режиму та зайву множину токенів.
- Оновлення screening-watchlist і прийняття сигналів винесено в окремі методи.
  Оновлення watchlist використовує ранні повернення замість вкладених умов.
- README узгоджено з єдиним виконуваним файлом; виправлено посилання між
  README та описом архітектури й відступ у TOML-прикладі.

Зміна типів полів `StrategyPlan` змінює Rust API цієї структури. Усі її
використання в workspace оновлено; стороннім споживачам потрібно прибрати
розпакування цих двох `Option`.

## Подальше очищення невикористаного коду

Після рев’ю видалено невикористані типи транзакцій і точних сум, сховище
артефактів аналізу та порожні залежності аналізаторів, пасивний API перегляду
кешу свічок, `ErrorEnvelope`, тестові обгортки `evaluate_mode` / `run_cycles`
і допоміжний candle-адаптер детектора. Детермінований алгоритм детектора
залишився на робочому шляху `detect_closes_with_scratch`.

Видалено crate `event-api` та внутрішній облік runtime-знімків, які не мали
споживача в застосунку. Офлайнова команда `status` більше не повертає поля
`runtime`, `runtime_status`, `runtime_activity`. Це зміна її JSON-виводу.
Режими `paper` / `live`, які застосунок не підтримував, тепер відхиляються
під час читання конфігурації. Прибрано залежності без використань і дубльовані
методи дескрипторів провайдера; каталог використовує статичні дескриптори.
